# Rejected handoff

A redesign handoff that compiles and gets sent back. Compare yours against it before writing the blueprint.

````
Redesigned the dashboard to feel cleaner and more modern. New indigo accent, cards with soft shadows and rounded corners, a gradient header, and a chart on every page so it feels data rich. The sidebar is icons only now. Typecheck, lint, and build pass. Ready to commit.
````

Why each part fails:

- `cleaner and more modern`: adjectives where the skill asks for measurements; every defect is a number with a `file:line` from the density audit, and the gain is quantified (rows per screen, content width, tiles that carry a trend).
- `New indigo accent`: every hue outside the roles the contract names is a defect, and the repository's contract and the organization's law name the roles, never this skill and never taste.
- `soft shadows and rounded corners`, `a gradient header`: elevation, radius by role, and motion are decided by the contract, not restyled per redesign; a real fork is decided in the blueprint with its basis.
- `a chart on every page`: a view drawn against data that does not exist or a table that is empty in production is deleted, not decorated, and what each page shows and in which form is decided through `plan-charts` from the question the page answers.
- `The sidebar is icons only now`: the contract's Frame row has the sidebar list places, each named for the entity it lists, and icons alone drop the names; labels go back when compression reads as broken.
- `Typecheck, lint, and build pass`: a green typecheck, lint, and build is not visual verification; the pass needs the declared browser order, both themes, and a narrow viewport.
- `Ready to commit`: no size and time estimate came before the run, no blueprint was written or approved before code, no contract was left in the app's AGENTS.md, and the tree stays uncommitted (committing composes `commit-changes`).
