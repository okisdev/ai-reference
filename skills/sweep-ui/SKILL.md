## Instructions

**The one rule: the sweep, not the user, finds what is wrong, so it runs find, fix and measure again on every surface until a fresh pass comes back clean, and the user is asked only about removing a capability, once, at the end.** A great sweep inventories every surface from the code, measures each on real data with the detail audit and a fixed set of questions, fixes in batches through shared components, re-measures until each surface is clean or a finding is accepted by name, and reports the counts before and after with what it opened and what it judged from code. Open [examples/sweep.md](examples/sweep.md) before reporting and check it against [examples/rejected.md](examples/rejected.md).

### Process

1. Parse `$ARGUMENTS`: the scope (the whole app by default, or a path) and `--report`, which skips steps 5 to 8 and reports the first pass in step 9's shape; without it the sweep fixes. Size the job (surfaces times states), tell the user the size and a time estimate, and run `date` at each step.
2. Resolve the governing design system (the nearest `DESIGN.md` or the `AGENTS.md` pointer, then its `extends:` chain) and list its component inventory from the code: the public views, styles, and modifiers of the UI module or design package, each with the pattern it owns. With no system, sweep for consistency between surfaces instead.
3. Inventory every surface from the code, not the navigation, with the presenter patterns in [references/surfaces.md](references/surfaces.md): pages and routes with each tab; every sheet, popover, alert, confirmation, inspector, panel, window, menu bar window, context menu, and toast; each surface's branches (empty, loading, error, permission denied, offline, first run, a record that no longer exists); the pages only some data sources unlock, reached in an account or home that has them; and every client of the product that renders the pattern (web, desktop, mobile, a marketing site sharing the kit) (seen: a composer and a select redesigned on the desktop app stayed old on the web app and the website). Record for each the file and line that presents it and the path a person takes to reach it.
4. Measure each surface on real data. A web surface goes through `verify-ui` (its real data step, including the preview of the new build on the deployed service when local data cannot reach a surface) and its detail audit after load and after each switch, in each viewport the product supports, trusting a clean result only once the surface shows its real data (seen: a pass over every page came back clean because a broken reload had left each page blank); a native surface is opened through the platform's accessibility actions and captured by its own window or simulator, then judged against the Measured lines of the system's taste. Answer the questions in [references/questions.md](references/questions.md) for every surface, counting the actions its main task takes for one item and for all of them. Mark each surface **on system** (built from the inventory's components), **partial** (mixed with the signals in [references/surfaces.md](references/surfaces.md)), **duplicate** (the same question or command as another surface), or **off system** (its own header, footer, buttons, pickers, fields or layout values, or a second implementation of a pattern the system owns), and record each finding with the surface, the measured value or the question it fails, and the rule it breaks (seen: a project log sheet was redesigned while the build log sheet beside it kept the old header and blue Done). A surface that cannot be opened is judged from code and marked so.
5. Classify the fixes before writing any: **component** when the defect lives in a shared component (fix it once, every surface follows), **pattern** when several surfaces build the same thing by hand (author or extend one component, then migrate them), **structure** when two surfaces answer the same question or a surface answers none (merge or delete), **surface** when only one surface is wrong. Order them component, pattern, structure, surface, because a shared fix closes many findings at once.
6. Fix without asking, in batches with disjoint files, every change that keeps what the product can do: layout, grouping, hierarchy, copy, which facts a row shows, a stored value migrated with its wording. Stop for nothing mid loop; collect each change that would remove a capability (a command, a setting, a view of data no other surface shows) as a question for the end, and keep the capability until the user answers; a fact the code in hand does not show (a component's props, a field's name) is a stated assumption with its fallback, never a question (seen: a redesign paused to ask whether to regroup ninety proxy cards, and the user asked why the sweep had to be told to find and fix its own problems).
7. Measure again after each batch, on the same surfaces, viewports and data, and continue until every opened surface's audit is clean, every surface's questions pass, and every surface is on system, or a remaining finding is accepted by name with its reason (data the product does not own, a label that repeats by design), after its taste line's fix was tried rather than argued away (seen: a disclosure wall was waved through as rows that already showed their content, and the user pointed at the same rows as broken). A batch that leaves a count unchanged or higher is reverted or fixed before the next batch, never carried.
8. Turn each signal a match can catch into a check for the system (`design-system` when installed, else the repository's own lint or UI check script), so the next sweep starts from a failing check; a copy or wording rule also sweeps the strings the server sends and the rows already stored, migrated in the same change.
9. Run the repository's full verification, then report: one table per fix class with each surface, how to reach it, the finding, and the fix; the audit counts per surface and the actions per main task, before and after; what was opened and in which viewports, and what was judged from code; the accepted findings with reasons; and the capability questions, asked together; when no surface could be opened, the report still states the loop's exit: each surface measured again after the fixes until its audit is clean or a finding is accepted by name.
