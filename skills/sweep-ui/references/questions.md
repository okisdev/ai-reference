# Questions the audit cannot answer

Ask each of every surface after the detail audit runs, in this order, and record a failing answer as a finding with the fix it implies.

1. **What does the person decide or do here?** Name it in one sentence. A section, row fact, badge, or caption that does not serve it goes; two surfaces with the same answer merge.
2. **What is said more than once?** A value shared by a run of items (a flag, a region, a name prefix, a type, a status) is said once by the group that holds them; a state in a header is not repeated in the body; a sentence on most items is the group's sentence, with the exceptions marked on their items.
3. **What has a different shape than its siblings?** Items of one kind share one geometry: the same height, the same columns, the trailing control in the same place. Optional content takes reserved space or moves to the hover tag, so no item grows.
4. **What moves without being asked?** Late data replaces a placeholder in place; a switch keeps the last result dimmed and the height held; a status fetched after the first paint never inserts a block above content.
5. **What does nothing?** A value that only says nothing is set, a control that cannot apply, a menu with one item, a dash in a column that is empty for every row: absent rather than drawn.
6. **What would a person with this data see?** Judge with the real account's volume and mix (ninety items, not three; a failing source, a long name, an offline device), because the defects live in the data the developer does not have.
7. **Is each command where it acts, and only there?** A command on many items moves to the group or the item's primary action; a command on the whole surface is in the top bar; a command shown twice keeps one home.
8. **What does the main task cost?** Count the actions the task people come for takes for one item and for all of them; a task that needs one open per item moves the state into the row, and the counts before and after go in the report.
