---
name: normalize-md
description: Challenge every markdown file in a repository (instruction files, design and feature docs, READMEs, guides) on whether it should exist and whether each line is true and worth its cost, then rewrite what stays into short rules, when docs drift from the code, grow with every change, or run too long, retiring CLAUDE.md within the size caps every harness reads.
argument-hint: "[scope]"
---

## Context

Markdown and caps: !`out=$(d="${CLAUDE_SKILL_DIR}"; python3 "${d:-$HOME/.agents/skills/normalize-md}/scripts/measure.py" . 2>/dev/null | sed -n '1,30p;/^## Markdown inventory/,$p' | head -70); echo "${out:-(measure script unavailable)}"`

Docs homes present: !`out=""; for f in README.md CONTRIBUTING.md ARCHITECTURE.md DESIGN.md docs; do test -e "$f" && out="$out $f"; done; echo "${out:-(none)}"`

Doc hook registered in: !`out=$(grep -l 'normalize-md/scripts/measure.py' "$HOME/.claude/settings.json" "$HOME/.codex/hooks.json" 2>/dev/null; find "$HOME/.grok/hooks" -name '*.json' -exec grep -l 'normalize-md/scripts/measure.py' {} + 2>/dev/null); echo "${out:-(none)}"`

## Instructions

**The one rule: every markdown file and every line in it earns its place against the code, its readers, and its cost, and nothing stays because it was there.** A file nobody reads, a line the code contradicts, a description the code already records, and a rule whose cost outweighs the failure it prevents all leave; what stays is the rules every change follows, each true and each worth its cost. Every removal is deliberate and carries its reason in the ledger, so the loss check catches accidents and never restores a deliberate cut (seen: a loss check restored eight as-built display details to feature docs, and would have restored a stale rule to keep today's copy byte for byte that froze all product copy). A rule about process or verification (what to run, when, how often, before what) is always weighed on its measured cost, because that cost recurs on every change while nobody rereads the rule (seen: a per-change check rule kept through three passes made every small change run end-to-end tests and a Linux rerun for over 20 minutes, beside a 60 second budget line that was never true). A pass is judged by the tree after it: `measure.py --since` shows whether the docs stopped growing with the code. The bar is [examples/challenge.md](examples/challenge.md) for the file and rule challenge, [examples/rewrite.md](examples/rewrite.md) for an instruction file, and [examples/read-path-doc.md](examples/read-path-doc.md) for a doc agents are pointed at: open the closest one before writing, and check the draft against [examples/rejected.md](examples/rejected.md).

Challenge every markdown file in scope, delete or propose deleting the ones without a reader, challenge every line of the rest for truth, need, and cost, rewrite instruction files and read-path docs into short normative documents, retire CLAUDE.md, prove nothing was lost by accident, and stop at an uncommitted tree.

### Process

1. Parse `$ARGUMENTS` (a scope path, default the repository root; every markdown file under the scope is in scope, and files above it are read for inheritance only). Keep the Context measurement as the before state, then run `python3 <this skill's directory>/scripts/measure.py <scope> --since "7 days ago"` (or the date of the last pass when history shows one) and keep its growth table: a doc that grew since is where this pass starts (seen: a pass judged only its own rewrite while the README manual it left as found grew from 122 KB to 140 KB in the next four days). A file with uncommitted changes is rewritten on top of the working copy, not skipped for being dirty (seen: it skipped an AGENTS.md with uncommitted changes that the user wanted it to build on), and the report names its pending diff (`git diff -- <file>` taken now). Skip it (`skip: uncommitted changes`) only when it changes again during the run (compare `git hash-object <file>` now with its value just before step 7 writes it) or another worktree (`git worktree list`) holds uncommitted changes to it, because another session may own it.
2. Read [references/standard.md](references/standard.md) (file challenge, rule cost, layout, caps, altitude test, routing table, coverage test, templates, placeholders and generators, README handling), then the project memory index, marking every rule-shaped topic (a trap, prohibition, or command every agent here needs, that the repository can publish, and that recurred, a review caught, or the index marks as a standing prohibition), then the repository's records of what its rules cost (CI run durations from `gh run list --json name,createdAt,updatedAt,conclusion`, timing files its scripts write, the last runs of each gating command), then its docs homes (README, CONTRIBUTING, ARCHITECTURE.md, `docs/`), so moved content lands in an existing home.
3. Redraw the doc set before challenging its files: list the questions its readers arrive with, name the one file that should answer each, and diff that set against the current files, so two files answering one question merge, a file answering none goes, and a question no file answers is reported, because a challenge run file by file accepts the current split as given. Challenge each file by the standard's File challenge, starting from the measurement's Markdown inventory: its purpose in one line, its readers with the proof of each, what breaks if it goes (a parser that loads it, a link that would dangle, a harness that loses its rules), and a sample of its claims checked against the tree. Delete in this pass a file with no reader, no parser, no inbound link, and no rule (a description the code records, a status page, a finished plan, a duplicate); propose deleting, with that evidence, a file that holds rules or that a person may open without a link; merge a file whose rules belong in another. A file a tool parses or an agent loads through a link (a skill body and its references, an eval prompt, a template shipped to users, a changelog a release step reads) keeps the format its owner sets, including that owner's conventions such as `(seen: ...)` clauses, and its lines are challenged for truth and need, never reshaped into the doc template or routed by the incident and status rows. A rules doc too large to merge into the instruction file within its caps becomes a read-path doc the instruction file points at section by section. Inventory each instruction file and read-path doc as well: harness owner, symlink target, `@import` lines, placeholders and generator blocks per the standard, the nested files whose scope it overlaps, and the docs it points at. Every placeholder is removed (a framework's fixed block, a scaffold preamble, a file-name title, an empty template heading, a TODO); the one obligation a block carried moves to the root as a single line; a generator with a switch is turned off in the same pass (Next.js: `agentRules: false` in that app's next.config) and one without is named in the report. A template directory and anything under a vendored or fixture tree are classified, left unchanged, and reported.
4. Build the ledger in the scratchpad, never in the repository: one row per clause of every file that stays (a bullet holding several rules yields several rows) and per claim of each marked memory topic, with its category, its reader, how its truth was checked, and a disposition: `keep`, `rewrite <true text>`, `move <destination>`, `drop <reason>`, or `propose <removal|rewrite>`. A `keep` names why the clause still earns its place; "it was there" is not a reason. Every rule also records the failure it prevents, what it costs each time it applies (time, steps, tokens, and how often it applies), and the evidence it still holds, measured from the records step 2 read and the standard's Rule cost; where the repository keeps no record (a skill body, a reference), the cost is the tokens and tool calls a run spends, written as unmeasured, and such a file is ledgered per step or bullet rather than per clause. A claim that a test, lint, or script enforces something stays unproven until the assertion is read (seen: a feature doc index claimed its check asserted an opening paragraph, which the check never did); a path or command is checked for existence, a number against its measurement, and a claim about the tree by grep; an untrue statement of fact (a description, a number, an enforcer claim, a command or flag that changed) is rewritten to the truth or dropped, never carried forward, while a rule whose premise is untrue, or a recipe that does not do what it claims, is `propose`. A clause repeated in the same file or in a file it links is dropped with the line that keeps it named, unless the file's owner wants the rule where it is used (a skill keeps its decision rules in its `SKILL.md`). An order to update a doc alongside the code ("a change to this file first", "add it to this file in the same change") is dropped, because the editing contract replaces it, and a line that makes a doc win over the code is reworded to cover its rules only, because a doc that wins whole lets a description outrank the code. A rule the code or a measurement contradicts, whose failure can no longer happen, or whose cost plainly exceeds the failure it prevents is `propose`, with the evidence and the replacement text, because the owner decides a rule's fate and the pass decides only its wording and truth. A rule a match on code can enforce (a banned value, a raw literal where a token belongs, a forbidden property or import) and that no check asserts yet is `propose` as a check (a lint rule, a test, a hook) with the rule kept until the check lands, because a check runs every time while a sentence is skipped once the context fills. A doc over 32 KB, or a repository past a few dozen files, is ledgered in parallel fresh subagents, each given its files or section, the standard, the step 2 records, and the marked memory topics, and returning rows in the ledger shape. A pass without a ledger is not a pass, a short maintenance pass included (seen: a pass with no ledger dropped two checklist steps of a design doc to meet its size target).
5. Write destinations before touching the source: incident narrative, rationale, and status lines go nowhere, since the commit, PR, issue, and tracker already carry them; an as-built description in an instruction or design doc goes nowhere because the code is its record (a manual's steps for people are not one) (a decision inside it that would regress silently becomes a test when one can assert it, else one rule); an accretion order is dropped because the editing contract replaces it; a decision with no public home that still gates later work goes to project memory only when it changes a later decision and nothing else records it (the pass never writes a memory topic about itself); a promoted memory claim lands in its file, and its topic is deleted once every claim in it has landed or been consciously dropped; package-scoped rules go down into that package's AGENTS.md (created when missing); contributor process rules go to CONTRIBUTING.md when the repository is public; agent-facing README sections come into AGENTS.md, leaving at most one pointer line, while the sections a person follows (install, usage, build, release steps) stay whole and only a line that binds an agent moves; an instruction file's pointer to a manual written for people is deleted and the manual's rules come into AGENTS.md or the doc that governs them; roles nobody can read from names go to the existing ARCHITECTURE.md or docs page, never a docs tree created for this; everything else goes nowhere.
6. Cover the tree: list the workspace packages and apps (`pnpm-workspace.yaml`, `package.json` workspaces, `turbo.json`, top-level `apps/` and `packages/`) and apply the standard's coverage test to every directory without an AGENTS.md, reading its README, manifest, and scripts for commands and traps; create the file only when at least one rule or command survives the altitude test, and record `covered by root` for the rest, and never give one to a folder that ships to users (a skill, a template), because it would install into their stores; a moved as-built description is never that rule, even rewritten as an imperative (seen: a pass created a nested AGENTS.md from a design doc's description of one page, reworded as "Draw the page as a document"). A repository with no root file gets the minimal root from the template.
7. Apply the ledger: delete the files step 3 deleted, rewrite each instruction file to the standard's template and each read-path doc to the read-path template, and edit every other kept file only where its ledger rows say. Every pointer to a read-path doc names, for each kind of change, the section that change needs; one rule per bullet with at most one because-clause; a rule an existing check asserts becomes a one-line pointer; a nested file holds only what the root does not. A `propose` row leaves its text as found, because the owner's answer, not the pass, changes it; it may still move to its destination with that text. Import lines stay byte-identical. Every `CLAUDE.md` and `.claude/CLAUDE.md` in scope is retired, because any one of them switches Claude Code back to CLAUDE.md-only loading: shared content merges into AGENTS.md, Claude-only content (plan mode, hooks, Claude-only tools) moves to `.claude/rules/`, and the file is deleted, a symlink with it. A repository that must serve Claude Code before 2.1.277, or on Bedrock, Vertex, or Foundry, keeps a stub holding `@AGENTS.md` beside every AGENTS.md and says so in the report. `CLAUDE.local.md` is never touched, and the report names each one. Then reread the result section by section, and give every survivor an agent could get from one `ls` or one manifest read a drop row before removing it.
8. Loss check in a fresh subagent with none of the rewriting context: hand it the old files (every changed or deleted markdown file and the marked memory topics), the new files, and the destinations, and ask for every obligation in the old files absent from the new files and their destinations; the brief says nothing about which drops were intended, because a check told its expected drops waves them through (seen: a brief that called two removed checklist steps restatements got them passed). Reconcile each item it names against the ledger: an item whose row drops or rewrites it with evidence stays as the ledger left it, while an item whose row proposes it, or that has no row, is an accident, because a proposal leaves its text as found until the owner answers: restore it, and give an unrowed item its row. Then rerun `python3 <this skill's directory>/scripts/measure.py <scope> --strict`, which exits non-zero only on a hard cap, and read its report for the rest: no generator left on beside a deleted block, no `claude-md` flag left except a `CLAUDE.local.md` or a stub layout the report explains, and every overflow past a target named.
9. Report, with the user's language: the files deleted and the files proposed for deletion, each with its readers and what would break; the challenged rules, each with the failure it prevents, its cost, the evidence, and the proposal with its replacement text; the lines rewritten because they were untrue; then per file the before and after bytes and lines, the Codex chain and Grok cap status, retired CLAUDE.md files, deleted generated files and disabled generators, created files with the coverage reason, promoted memory topics, moved and dropped items with reasons, the loss check items and how each was reconciled, the pending diff of each file rewritten over uncommitted changes, skipped files, the growth table from step 1, the `measure.py --strict` command a repository can wire into CI to fail on a hard cap, and the doc hook. `measure.py --hook` flags what one write adds as a PostToolUse hook in every harness that edits here: Claude Code in `~/.claude/settings.json` and Codex in `~/.codex/hooks.json`, both on the matcher `Write|Edit` (Codex maps it to `apply_patch` and runs the hook only once it is trusted), and Grok in a `~/.grok/hooks/*.json` file on the matcher `Edit|Write`. Name each harness the Context line shows without it, because its edits go unchecked (seen: Codex made at least 20 doc edits in four days that a Claude-only hook never saw). Stop at an uncommitted tree; committing composes `commit-changes` when installed, and shipping composes `ship-pr` when installed.

### Rules

- A rule the file says nothing enforces is never dropped silently; it moves to the top of Rules unless the challenge proposes its removal to the owner with evidence.
- User-level instruction files (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.grok/AGENTS.md`) stay out of a repository or home-directory scope, because every harness loads them in every repository; when the user names one, only its lines are challenged for truth, need, and cost under the file's own stated constraints, and the template, CLAUDE.md retirement, and coverage never apply (seen: an explicit ask to tidy the global file met a rule that put it out of scope).
- Narrative never flows back into an instruction file from memory or a session, while a rule does and then leaves memory; content crosses between README and AGENTS.md only by reader, and neither keeps the other's copy beyond one pointer line.
- A size target is never met by cutting a rule; a rule leaves only through its ledger row, and overflow is reported.
- A placeholder never survives because it might come back; the switch lands in the same pass when one exists, and the marker is reported when none does.
- A new file with nothing to say is never created; absence is the valid outcome.
- No new dependency; the measure script stays Python 3 standard library.
- Edit markdown files with the editing tool, never a script or heredoc, because the doc hook sees only the editing tool's writes (seen: two AGENTS.md files were appended through a Python heredoc that no hook saw).
