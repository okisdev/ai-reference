## Instructions

**The one rule: docs hold the rules every change follows, not a record of the code, and no rule is lost getting there.** Description, history, and inventory move or go with the reason written down, and an order to update a doc alongside the code ("a change to this file first", "add it to this file in the same change") is dropped, because the editing contract replaces it, and a line that makes the doc win over the code is reworded to cover rules only (the code is fixed where it breaks one), because a doc that wins whole lets a description outrank the code; an obligation never goes to meet a size, and overflow is reported instead. A pass is judged by the tree after it, not by its own checks: `measure.py --since` shows whether the docs stopped growing with the code. The bar is a rewrite where every old clause is kept, moved to a named home, or dropped for a stated reason, as in [examples/rewrite.md](examples/rewrite.md) for an instruction file and [examples/read-path-doc.md](examples/read-path-doc.md) for a doc agents are pointed at: open the closer one before rewriting, and check the draft against [examples/rejected.md](examples/rejected.md).

Rewrite every instruction file and read-path doc in scope into a short normative document: keep the rules, move everything else to its owning home, take manuals written for people off the agent's path, remove what generators wrote, add a file only where the tree needs one, prove nothing load-bearing was lost, and stop at an uncommitted tree.

### Process

1. Parse `$ARGUMENTS` (a scope path, default the repository root; every instruction file and read-path doc under the scope is processed, and files above it are read for inheritance only). Keep the Context measurement as the before state, then run `python3 "$HOME/.agents/skills/normalize-agents-md/scripts/measure.py" <scope> --since "7 days ago"` (or the date of the last pass when history shows one) and keep its growth table: a doc that grew since is where this pass starts, whichever table lists it (seen: a pass judged only its own rewrite while the README manual it left as found grew from 122 KB to 140 KB in the next four days). A file with uncommitted changes is rewritten on top of the working copy, not skipped for being dirty (seen: it skipped an AGENTS.md with uncommitted changes that the user wanted it to build on), and the report names its pending diff (`git diff -- <file>` taken now). Skip it (`skip: uncommitted changes`) only when it changes again during the run (compare `git hash-object <file>` now with its value just before step 7 writes it) or another worktree (`git worktree list`) holds uncommitted changes to it, because another session may own it.
2. Read [references/standard.md](references/standard.md) (layout, read-path docs, caps, altitude test, routing table, coverage test, templates, placeholder and generator dispositions, README handling), then the project memory index via `use-project-memory`, marking every rule-shaped topic (a trap, prohibition, or command every agent here needs, that the repository can publish, and that recurred, a review caught, or the index marks as a standing prohibition), then the repository's docs homes (README, CONTRIBUTING, ARCHITECTURE.md, `docs/`), so moved content lands in an existing home.
3. Inventory each file in scope: harness owner, symlink target, `@import` lines, placeholders and generator blocks per the standard, the nested files whose scope it overlaps, the READMEs the measurement flags as carrying agent-facing lines, the read-path docs it lists, required and pointed alike, each with the line that points at it, and the large docs it lists off the agent's path. Every placeholder is removed (a framework's fixed block, a scaffold preamble, a file-name title, an empty template heading, a TODO); a file that was only placeholder is deleted; the one obligation a block carried moves to the root as a single line; a generator with a switch is turned off in the same pass (Next.js: `agentRules: false` in that app's next.config) and one without is named in the report. A template directory and anything under a vendored or fixture tree are classified, left unchanged, and reported.
4. Build the ledger in the scratchpad, never in the repository: split each editable file, each read-path doc, and each flagged README's agent-facing sections, into clauses (a bullet holding several rules yields several entries), split each marked memory topic into its claims, each a clause of its own, classify each clause with the standard's categories and its reader (a person or an agent), and assign `keep`, `move <destination>`, or `drop <reason>`. A clause that claims a test, lint, or script enforces it stays a rule until the enforcer is found and its assertion read. A path or command the clause names is checked for existence, and a factual claim about the tree (a directory holds no X, a file is the only Y) is checked by grep; a stale one is corrected or dropped, never carried forward. A read-path doc over 32 KB is ledgered section by section in parallel fresh subagents, each given one section and the standard and returning rows in the ledger shape, so no single context holds the whole doc. A pass without a ledger is not a pass, a short maintenance pass included: every clause it removes or moves has a row (seen: a pass with no ledger dropped two checklist steps of a design doc to meet its size target).
5. Write destinations before touching the source: incident narrative, rationale, and status lines go nowhere, since the commit, PR, issue, and tracker already carry them, an as-built description goes nowhere because the code is its record (a decision inside it that would regress silently becomes a test when one can assert it, else one rule), an accretion order is dropped because the editing contract replaces it, and a decision with no public home that still gates later work goes through `use-project-memory`'s admission test (the pass never writes a memory topic about itself); a promoted memory claim lands in its file, and its topic is deleted through `use-project-memory` only once every claim in it has landed or been consciously dropped, otherwise rewritten to the claims that stay; package-scoped rules go down into that package's AGENTS.md (created when missing); contributor process rules go to CONTRIBUTING.md when the repository is public; human-facing content goes to the README when it lacks it; agent-facing README sections come the other way into AGENTS.md, leaving at most one pointer line in the README; an instruction file's pointer to a manual written for people is deleted and the rules inside that manual come into AGENTS.md or the doc that governs them, while what it tells a person stays where it is (the standard's Read-path docs); roles nobody can read from names go to the existing ARCHITECTURE.md or docs page, never a docs tree created for this; everything else goes nowhere.
6. Cover the tree: list the workspace packages and apps (`pnpm-workspace.yaml`, `package.json` workspaces, `turbo.json`, top-level `apps/` and `packages/`) and apply the standard's coverage test to every directory without an AGENTS.md, reading its README, manifest, and scripts for commands and traps; create the file only when at least one rule or command survives the altitude test, and record `covered by root` for the rest; a moved as-built description is never that rule, even rewritten as an imperative (seen: a pass created a nested AGENTS.md from a design doc's description of one page, reworded as "Draw the page as a document"). A repository with no root file gets the minimal root from the template: title line, commands, and editing contract.
7. Rewrite each file to the standard's template, a read-path doc to the read-path template, and every pointer to a read-path doc into one naming, for each kind of change, the section that change needs, never one read of the whole doc before every change: one rule per bullet with at most one because-clause naming the failure it prevents, a rule an existing check asserts becomes a one-line pointer, a nested file holds only what the root does not. Import lines stay byte-identical. Every `CLAUDE.md` and `.claude/CLAUDE.md` in scope is retired, because any one of them switches Claude Code back to CLAUDE.md-only loading: shared content merges into AGENTS.md, Claude-only content (plan mode, hooks, Claude-only tools) moves to `.claude/rules/`, and the file is deleted, a symlink with it. A repository that must serve Claude Code before 2.1.277, or on Bedrock, Vertex, or Foundry, keeps a stub holding `@AGENTS.md` beside every AGENTS.md instead and says so in the report. `CLAUDE.local.md` is never touched, and the report names each one, because it turns AGENTS.md loading off for its owner too. Then reread the result section by section and delete every survivor an agent could get from one `ls` or one manifest read, because filler survives the first pass in slimmed form, most often as pointers that only say what a directory holds.
8. Loss check in a fresh subagent with none of the rewriting context: hand it the old files (instruction files, read-path docs, any edited README, and the marked memory topics), the new files, and the destinations, and ask for every obligation in the old files absent from the new files and their destinations; the brief says nothing about which drops were intended or why, because a check told its expected drops waves them through (seen: a brief that called two removed checklist steps "the two DESIGN.md checklist items that restate Principles 1 and 2" got them passed). Restore or consciously drop each item it names, and record the reason. Then rerun `python3 "$HOME/.agents/skills/normalize-agents-md/scripts/measure.py" <scope> --strict`: every file within the caps, no generator left on beside a deleted block, no `claude-md` flag left except a `CLAUDE.local.md` or a stub layout the report explains, every overflow past a target named with the rules that could not be cut, every pointed doc and large doc over its target named, and every accretion order gone or named with the reason it stays.
9. Report per file, read-path docs included, the before and after bytes and lines, the Codex chain and Grok cap status, retired CLAUDE.md files, deleted generated files and disabled generators, created files with the coverage reason, promoted memory topics, moved items with destinations, dropped items with reasons, contradictions resolved, the pending diff of each file rewritten over uncommitted changes, skipped files, the growth table from step 1, the `measure.py --strict` command a repository can wire into CI, and the doc hook. `measure.py --hook` flags what one write adds as a PostToolUse hook in every harness that edits here: Claude Code in `~/.claude/settings.json` and Codex in `~/.codex/hooks.json`, both on the matcher `Write|Edit` (Codex maps it to `apply_patch` and runs the hook only once it is trusted), and Grok in a `~/.grok/hooks/*.json` file on the matcher `Edit|Write`. Name each harness the Context line shows without it, because its edits go unchecked (seen: Codex made at least 20 doc edits in four days that a Claude-only hook never saw). Stop at an uncommitted tree; committing composes `commit-changes`, shipping composes `ship-pr`.

### Rules

- A rule the file says nothing enforces is never dropped; it moves to the top of Rules.
- User-level instruction files (`~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, `~/.grok/AGENTS.md`) are never in scope, even when the scope is the home directory, because every harness loads them in every repository.
- Narrative never flows back into an instruction file from memory or a session, while a rule does and then leaves memory; content crosses between README and AGENTS.md only by reader, and neither keeps the other's copy beyond one pointer line.
- A size target is never met by deleting a rule; overflow is reported instead.
- A placeholder never survives because it might come back; the switch lands in the same pass when one exists, and the marker is reported when none does.
- A new file with nothing to say is never created; absence is the valid outcome.
- No new dependency; the measure script stays Python 3 standard library.
- Edit instruction files and read-path docs with the editing tool, never a script or heredoc, because the doc hook sees only the editing tool's writes (seen: two AGENTS.md files were appended through a Python heredoc that no hook saw).
