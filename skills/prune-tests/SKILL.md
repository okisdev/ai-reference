name: prune-tests
description: Prune the tests that guard no behavior or guard it at too high a cost (wrong layer, fixed waits, leftover state, repeated fixtures, duplicates), when tests are bloated, slow, flaky, or redundant, or a suite takes too long to run.
argument-hint: "[path]"

## Context

Largest test folders: !`out=$(git ls-files 2>/dev/null | grep -E '(\.(test|spec)\.[cm]?[jt]sx?|_test\.(go|py)|(^|/)test_[^/]*\.py|Tests?\.swift|Tests?\.kt)$' | sed -E 's|/[^/]*$||' | sort | uniq -c | sort -rn | head -6); echo "${out:-(none)}"`
Test commands: !`out=$( { test -f package.json && jq -r '.scripts // {} | to_entries[] | select(.key | test("test|e2e|spec|check|verify")) | .key + ": " + .value' package.json 2>/dev/null; grep -E '^(test|e2e|check|verify|full)[A-Za-z_-]*:' Makefile 2>/dev/null; } | head -10); echo "${out:-(none)}"`
Fixed waits in tests: !`out=$(git grep -c -E 'waitForTimeout|time\.sleep|Thread\.sleep|Task\.sleep|[^a-zA-Z_]sleep\(|setTimeout\([^,]*, *[0-9]{3,}\)' -- '*test*' '*spec*' '*Tests*' 2>/dev/null | sort -t: -k2 -rn | head -6); echo "${out:-(none)}"`

## Instructions

**The one rule: every test left guards a behavior something relies on, at the lowest layer that can catch its regression, deterministically, and fails only when that behavior regresses.** A great pass leaves fewer and faster tests that guard the same behavior, proves it with the same suites timed before and after, and names for every moved or deleted test what still guards its behavior. The bar is [examples/pass.md](examples/pass.md): open it before reporting, and check the draft against [examples/rejected.md](examples/rejected.md).

### Process

1. Parse `$ARGUMENTS` (a path, defaulting to every test in the repository; a suite named in the ask, such as "the e2e tests", limits it). Tell the user the size from the Context (test files, the largest folders) and a time estimate before starting, run `date` at the start of each step, and tell the user when a step runs past twice its share.
2. Measure before judging: run each suite in scope once with its runner's per-test durations (`vitest --reporter=json`, `playwright test --reporter=json`, `pytest --durations=20`, `go test -count=1 -json` so cached results do not fake the time, an `xcodebuild` result bundle, the JUnit XML a forced Gradle test task writes), and record the wall time, the test count, the twenty slowest tests, and any failure. When a suite is too slow to run whole, take its durations from the repository's own timing files or its CI test-report artifacts, since run timestamps include queueing and name no test. Classify each baseline failure as pre-existing or flaky before judging its suite. This baseline picks what to judge and its test counts are what the report compares against; the report's wall times come from step 6's alternating runs.
3. Judge every test on two axes, writing one row per test (or per describe block in a generated or table test) in a scratchpad ledger: the behavior it guards, its value verdict, its cost verdict, and the disposition. Past about fifty files, split the ledger by folder across fresh subagents, each given its files, this step, and the baseline durations, returning rows in the ledger shape and the count of files it read in full, then merge the rows by behavior to find copies across folders before any disposition is final. A slice that read fewer files in full than it was given is dispatched again or its area is reported as partial, because a grep triage finds waits but cannot judge value (seen: six of ten ledger slices read 5 to 33 percent of their files and returned keep for the rest). Check every row against the code before applying it, because reviewers misread contracts as implementation.
   - Value. Keep a test only when it changes only when the intended behavior changes and fails only when that behavior regresses. Prune one that depends on the past (asserts removed code stays gone, such as a deleted module staying absent from its old path, because bringing it back is a decision, not a regression, unless the absence is a contract such as a secret, a license, or a public export, which is asserted at the public surface instead), on nothing (no code change can fail it: it asserts the browser renders a `<button>`, mocks the unit under test and asserts the mock, or asserts what the type system guarantees), or on the implementation (it changes whenever the code does: private state, internal call order that no caller can observe, which helper ran, or an expected value computed by the same logic as the code). An assertion whose failure a caller would see is not the implementation even when it reads like one: a value equal to its own JSON round trip (it must survive serialization), a reference kept identical (consumers skip work on identity), the call count of a path the test name says must not run, a committed golden snapshot, or a secret's absence (seen: all five were flagged as never failing or as implementation in one audit). Prune a copy of a behavior another test already guards, naming that test.
   - Cost. A valuable test can still be written at the wrong price. Wrong layer: an end-to-end or UI test earns its launch only by crossing a boundary a lower test cannot (a real process, a terminal, native UI or an OS dialog, file watching, the network, persistence across a restart); logic a unit test can prove moves down, keeping one higher test for the wiring it crossed (a bridge, IPC, a route) unless another test already crosses it. Fixed waits: a sleep, a timeout that is waited out on the passing path, or a fake that never signals completion (a fake process whose `kill()` never emits `exit`) is replaced by waiting on the condition, or by a fake clock where the code under test owns the timer; elapsed time that is itself the behavior (a debounce, an expiry, a grace period) keeps one test that drives it, and a wait that stands for internal state nothing publishes is reported as needing a seam, never replaced by a shorter guess. Leftover state: a test that passes only after another test, on a warm simulator, or in a shared folder sets up its own state. Repeated expensive fixtures: an app launch, a real repository, or a database rebuilt per test where an immutable template copied per test gives the same isolation, keeping one test that builds the fixture from scratch. Multiplied cases: generated cases that repeat one rule collapse to one case per rule. Unchecked output: a screenshot never compared or a value only printed is asserted, deleted, or reported when what it should assert is the owner's call, while a screenshot written only behind an opt-in variable for a person to look at is tooling. Several unrelated behaviors in one test split only when a failure there cannot say which broke, because splitting alone removes no cost (seen: an audit of 136 end-to-end specs found 12 that unit tests could prove, 74 fixed sleeps, a first test asserting seven things, and 2,576 generated i18n cases backing 22 rules; a UI test waited 10 seconds for a paste dialog on every page).
   - Disposition: `keep`, `delete <the test that still guards it, or why nothing must>`, `rewrite <the behavior it asserts instead>`, `move down <the layer and file>`, `fix cost <the wait, state, or fixture change>`, or `report <the behavior that needs the owner's decision>`.
4. Apply the ledger. Delete; rewrite against what callers see; move a test down by writing the lower test first, watching it fail on the planted regression from step 5, then deleting the higher one; replace fixed waits and leftover state at their cause. Delete production code and test helpers that existed only for removed tests, and fold copied helpers into the shared one the repository already has. Add no test beyond a replacement, because this pass removes cost.
5. Prove nothing became unguarded: for every moved, rewritten, or cost-fixed test, plant the regression it guards (flip the line the behavior depends on), run the new test and see it fail, then restore the line; for every deletion under a copy, plant the shared behavior's regression and see the surviving test fail. A behavior left with no guard is a finding to report, never a silent deletion.
6. Rerun step 2's suites with the same reporters and the repository's own full ladder under `set -o pipefail`, timing before and after in two checkouts of the same base run alternately, because wall time on a shared machine moves with its load (seen: a full suite read 15 percent slower while load rose from 9 to 28, and the same files timed identical alone). A negative assertion whose wait was replaced still waits at least as long as the path that could misbehave; read that path's timing in the production code. Run every changed test several times through the runner's own repeat option (Playwright `--repeat-each`, Go `-count` with `-shuffle=on`, XCTest `-test-iterations`), alone and shuffled where the runner supports it, and on a fresh environment (a new simulator, an empty data folder), to show it is deterministic.
7. Stop the cause at write time: for each cost pattern found three or more times that a match can catch (a sleep call, `waitForTimeout`, an end-to-end file for a module with no boundary), propose a check (a lint rule, a test, a hook) and the one-line admission rule for the repository's AGENTS.md or its test folder's AGENTS.md (`normalize-md` when installed weighs it), because tests written the same way grow back after every pass; lower the repository's own ratchets (wait counts, test budgets) to the new counts in the same pass. A rule there that orders a suite to run on every change is reported with its measured cost from step 2 for the owner to decide.
8. Stop at an uncommitted tree and report, with the user's language: the before and after table (tests, wall time per suite, slowest tests), the counts per disposition, each moved or deleted test with what still guards it, the behaviors found unguarded, the proposed checks and admission rule, and anything not run. Committing composes `commit-changes` when installed.

### Rules

- Never weaken, skip, or delete a failing test to make verification pass; a failing test is a finding.
- Never add a retry, raise a timeout, or quarantine a test as a fix, because each hides the cost or the race instead of removing it.
